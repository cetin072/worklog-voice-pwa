# Mobile Web UX Parity — #351

상태: Draft / main 미병합

사용자 체감 변경:
- 하단 홈/업무/일정·알림/설정 탭을 제거하고 Home-first 구조로 단순화
- 상단 검색/설정만 유지
- 웹 브리핑 V2처럼 지난 것·오늘·다가오는 업무·기한 없는 업무를 색상과 구간으로 구분
- 각 업무 구간은 기본 3건을 보여주고 초과분은 `N개 더 보기 / 접기`
- 각 업무에서 바로 완료 처리하고 실행 취소 가능
- 업무 제목·날짜·시간을 같은 브리핑 화면에서 inline 수정
- 오늘/다가오는 일정을 홈 브리핑 안에서 바로 확인
- 일정마다 Calendar 연결 상태와 실제 계정/캘린더 정보를 지속 표시
- 이미 Calendar에 연결된 일정은 업무 날짜/시간/제목 수정 후 권한 재요청 없이 기존 mapping을 자동 갱신
- 다른 Calendar를 선택만 한 상태와 실제 연결 상태를 구분하고 `선택한 캘린더로 이동` 문구 사용
- 일정마다 현재 알림 간격을 `이 일정 알림` 문맥으로 지속 표시
- Calendar/알림 상세 설정은 펼치기/접기로 필요할 때만 노출
- 알림 클릭 시 별도 일정 탭 대신 홈의 해당 일정 영역으로 복귀
- 빠른 음성메모를 일반 카드에서 하단 고정 Quick Voice Dock으로 변경
- 중앙 마이크·녹음 타이머·직접 입력·파일 저장 상태를 한눈에 표시
- 하단 Quick Voice Dock을 Android system safe area 위에 배치
- 작은 화면 닫기 버튼 clipping을 flex/shrink 구조로 완화

기술 원칙:
- 기존 웹 `briefing-v2` / `worklog-edit` 계약 재사용
- 기존 Data Core mutation / Calendar Provider / Expo Notifications 유지
- 새 dependency 없음
- Google OAuth / 기존 Calendar permission 등 untouched 기반은 전체 재검수하지 않음
- 전체 Human QA 반복 대신 #351 변경 범위만 검수

현재 Quick Voice 주의:
- 이 PR에서는 비주얼/조작 parity만 개선
- 녹음 종료 후에는 아직 로컬 파일 저장 단계
- 음성 → STT → 업무 저장 → 브리핑 즉시 반영은 #353에서 연결
