# 설치 QA 피드백: 홈 행·알림·수정·Calendar

대상: #537 `qa/my-management-integrated`. 설치본 `3437688` 이후의 코드 수정이며 새 APK·main 병합·Production/Play 배포·DB 변경은 하지 않았다.

## 확인한 원인과 변경

- HomeTaskRow의 날짜와 알림이 두 줄짜리 오른쪽 버튼 묶음 밖에 있어 제목과 날짜 사이가 벌어졌다. 제목/날짜/시간과 작은 아이콘을 같은 왼쪽 열에 모으고 오른쪽 수정/삭제/완료를 위쪽에 정렬했다. 메모도 위 정렬, 기존 공통 폰트/버튼 스타일 및 44–48pt 터치 영역 재사용. 제목 줄 수 제한/접기나 사용자 글꼴 배율 제한을 추가하지 않았다.
- 메모의 표시 버튼을 `완료`로 통일했다. 내부 동작은 기존 acknowledged/active 및 실행 취소 그대로다. 업무 상태 완료로 변환하지 않는다.
- 알림 Provider가 화면·분 단위 scope와 briefing 객체 참조 변화마다 증거를 빈 값으로 바꾸고 있어 확인된 예약과 확인 필요가 번갈아 보였다. 소유자 scope와 갱신 계기를 분리하고 동일한 표시 데이터는 재조회 중 기존 검증 결과를 유지한다. 내용/사용자/client 변경, 세션·알림 epoch 무효화는 즉시 이전 증거를 숨기고 실제 재조회 실패도 확인 필요로 반영한다.
- 알림은 종과 작은 배지로 표시: 초록 ✓ 예약 확인, 회색 − 없음, 빨강 ! 권한 필요, 파랑 ? 확인 필요. 색에만 의존하지 않으며 화면 읽기에는 전체 상태 문구가 남는다. 터치 시 기존 상세/설정 경로, 예약 여부 판단/OS 증거 검증은 그대로다. 반복업무는 일반 일정 예약 증거가 없으면 ?이며 예약됨을 임의 표시하지 않는다.
- 수정창은 기존 제목·날짜·시간을 즉시 보여주고 확인 중에도 제목/날짜/시간을 수정할 수 있다. Home만 opt-in하며 검색 등 기존 호출자는 그대로다. 큰 로딩 표시 대신 저장 전 확인 안내를 사용한다. 늦은 서버 응답은 dirty 필드를 덮어쓰지 않는다. 날짜만 고쳤을 때 기존 서버 시간이 유실되지 않도록 각 필드 dirty 상태를 분리했다. **최신 소유자 상세 조회 자체는 유지**하며 성공 전 저장/종류 변환은 막아 오래된 목록 값으로 덮어쓰지 않는다. 실패 시 성공 표시 없이 입력과 재시도를 유지한다.
- HomeTaskRow에서 Google 전송 동작이 숨겨져 있었다. 연결이 유효한 날짜 있는 일반 업무의 왼쪽 아이콘 행에 기존 CalendarExportPreview를 compact 모드로 한 번 배치했다. 반복업무에는 일반 record ID 전송을 연결하지 않는다. 연결은 계속 설정에서만 한다. 미리보기/명시적 전송/최신 원본 확인/중복 방지 그대로이며 연결·표시만으로 Google 이벤트를 쓰지 않는다. 설정에 자동 등록이 아니라는 설명 추가. 앱 종료/로그아웃/만료 후 재연결 정책은 바꾸지 않았다.
- 하단의 홈 `내 관리` 바로가기를 상단 설정 근처 `관리` 버튼으로 이동했다. 세 영역은 접근성 설명에 명시하고 설정 진입점은 보존했다. 홈 전체 순서나 하단 탭은 바꾸지 않았다.
