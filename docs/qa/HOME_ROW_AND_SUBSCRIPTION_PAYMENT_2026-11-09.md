# 홈 행 표시 복원 · 구독 결제수단

기존 구독 PR #534에서 이어간다. 앱 소스 수정 후 사용자의 추가 승인으로 아래 결제수단 DB migration만 적용했다. main 병합, APK 제작, Production/Play 배포는 하지 않았다.

## 변경

- 기존 메모·참고의 제목(15/700), 보조 글자(13), 연필(18), 삭제(12/900), 48px 버튼 스타일을 `record-row-styles.ts`에서 그대로 재사용한다.
- 홈 업무 행은 메모처럼 연필·삭제와 완료 버튼을 표시한다. 펼친 상세에서 같은 동작을 중복 노출하지 않는다. 기존 삭제 확인·완료·수정 함수는 그대로 사용한다.
- 다가오는 업무의 날짜를 펼치기 전에 보조 글자로 표시한다. 캘린더의 오늘 외 날짜 일정에도 서울 기준 날짜를 표시한다.
- 개인 일정 관리의 제목·날짜·연필·삭제 버튼도 같은 스타일을 쓴다. 기존 권한·수정 충돌·삭제 확인 경계를 유지한다.
- 구독에 선택 결제수단(미등록/카드/자동이체/기타)과 카드명·은행 별칭을 추가한다. 수단 변경 시 이전 별칭을 비운다. 원문·소유자·기존 알림 계산에는 영향을 주지 않는다.
- `worklog.subscriptions`의 nullable `payment_method`, `payment_name` 컬럼 추가 migration을 CLI로 생성했다. **사용자 승인 후 ERP 공유 프로젝트의 worklog 스키마에 적용 완료했다.** 앞서 적용된 기본 구독 테이블을 재적용하지 않았다. 앱 코드가 아직 미배포인 상태와 구분한다. 다른 환경에서 컬럼 미준비 시 성공으로 보거나 선택값을 조용히 버리지 않고 준비 중 안내를 표시한다.

## 검증과 한계

- 실제 TS 폼을 실행해 카드명 입력·저장, 자동이체 전환 시 카드명 제거, 결제수단 비우기를 확인한다.
- 실제 저장소의 INSERT payload, 서버 행→수정 초안→목록 표시를 확인한다.
- 독립 PGlite DB에 기존 migration과 추가 migration을 순차 적용해 기존 행 null 보존, 본인 데이터만 조회·수정, 타인 접근 차단, 허용 수단·이름 길이 제약을 확인한다. 운영 DB를 사용하지 않는다.
- 홈/캘린더 런타임 검사에서 미래 날짜 노출 및 수정·삭제·완료/실행취소 연결을 확인한다. 결제수단 UI 추가가 일정 알림이나 계정 경계를 바꾸지 않는다.
- 전체 Node 회귀·모바일 TypeScript·Android Metro export로 검사한다. APK는 새로 만들지 않는다.
- 실제 휴대폰의 폰트 배율·화면 배치·구독 저장/알림 수신은 미검증이다. 실제 사진이나 사용자 기록을 테스트에 사용하지 않는다.
- 기존 SHA 9405a6c APK는 이번 수정 전 파일이다. 그 실행의 에뮬레이터 사진 선택 검사는 재실행에서도 실패했으므로 성공 근거로 재사용하지 않는다.


## 승인된 공유 DB 적용 결과

- 대상: `jgsxpdflgkqroecfjzxq` (`taejang-phase1-staging`), `worklog.subscriptions`. 이름에 staging이 있으나 ERP와 공유하는 실제 연결 프로젝트임을 확인했다.
- 사용자 승인: 이 채팅의 “응 적용해” (결제수단용 선택 필드 2개 추가).
- 원격 migration: `20261109144344 / subscriptions_payment_method`. 로컬 CLI 생성 파일의 SQL 내용은 유지하고 파일 버전을 실제 원격 이력과 맞췄다. 다른 migration은 실행하지 않았다.
- 적용: nullable text `payment_method`, `payment_name`, 허용 수단·이름 길이·수단 없는 이름 금지 CHECK 3개. 5초 lock timeout, 30초 statement timeout으로 해당 DDL만 실행했다.
- 기존 구독 **10건**의 건수와 새 필드를 제외한 전체 행 해시가 적용 전후 일치했다. 새 선택 필드는 기존 10건 모두 null이다. 실제 사용자 기록을 수정하거나 테스트 행을 추가하지 않았다.
- RLS 활성·소유자 정책 3개·테이블 권한이 적용 전후 동일했다. authenticated의 새 컬럼 SELECT 가능, anon SELECT 불가를 확인했다. read-only authenticated 쿼리로 새 컬럼 조회 문법·권한도 확인했다.
- 보안 advisor의 기존 분류/건수는 적용 전후 같았으며 subscriptions 관련 항목은 없었다. 프로젝트 전체가 경고 0건이라는 의미는 아니다.
- DB 준비와 앱 설치는 별개다. 기존 9405a6c QA APK에는 선택 결제수단 입력 UI와 이번 홈 행 수정이 포함되지 않는다. 새 APK는 제작하지 않았다.
