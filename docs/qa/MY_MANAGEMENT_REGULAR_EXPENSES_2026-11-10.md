# 정기지출 확장 — 검증 기록

기존 #534 화면·입력 파서·결제수단·날짜 계산·로컬 알림을 재사용. 구독/보험/자동이체/기타 유형, 변동 예상액, 실제 월 예정액과 환산액 구분, 회차 납부 확인과 종료 후 이력을 추가했다. 홈 행 복원은 보존한다.

- 원격 DB는 구조·migration·RLS만 읽었다. 기본/결제수단 migration 적용 확인, 재적용 없음. 실제 사용자 행으로 테스트하지 않았다.
- 새 regular_expenses_v1 migration은 PGlite 격리 DB만 실행했다. 소유자/타인/anon 권한, 잘못된 회차, 10회 중복 납부 확인, 종료 후 이력 조회와 신규 납부 차단을 실제 SQL로 검증했다.
- 이전 단계 Node 전체 1241/1241 PASS. 최신 통합 검사는 통합 기록을 따른다. TypeScript PASS. Android Metro export PASS. 새 의존성·서버·AI·운영 데이터 변환 없음.
- 납부 확인 응답 유실 뒤 동일 회차 읽기 확인/확인 불가 오류를 실제 저장 함수에서 검증했다. 구독 생성은 화면 내 안정적 UUID를 재사용한다.
- 변동 금액 납부 확인은 입력한 예상액 스냅샷이며 은행 거래 내역이 아니다. 납부 이력은 500개씩 순차 조회하고 화면 최근 20개를 표시한다. 별도의 과거 이력 탐색 화면은 V1에 추가하지 않았다.
- Android 실행·실기기 글꼴 배율·알림 전달·320/390 화면 캡처는 아직 미검증. Metro 성공을 기기 PASS로 취급하지 않는다. 기존 사진 선택 에뮬레이터 실패도 닫지 않는다.
- 새 스키마 원격 적용 전에는 확장 화면이 준비 중 오류를 표시한다. APK 생성·원격 migration·main 병합·Production/Play 배포 없음.

추가 검사: 납부 확인 회차는 예정 알림에서 제외하고 다음 회차는 유지한다. logout과 지연된 권한 응답 경합에서 이전 알림 재예약을 차단한다. 새 납부 이력이 명시적 계정 삭제의 기존 cascade를 막지 않는지 격리 SQL로 확인했다. 원격에는 적용하지 않았다.

## 저장·알림 경계 보강

목록은 exact count가 일치하는 전체 스냅샷만 반영한다. 납부 이력은 500건씩 순차 조회하고 총계 변경·누락·5,000건 초과는 명시적으로 확인 필요로 처리한다. 화면은 최근 20건을 표시하며 과거 이력은 삭제하지 않는다. 예상 금액의 납부 확인은 실제 거래 연동이 아닌 예상액 기준임을 표시한다.

인증 준비 전이나 최초 조회 실패에는 기존 본인 알림을 비우지 않는다. 예약의 소유자를 확인해 다른 계정 예약만 제거한다. 소유자 없는 기존 구독 알림은 제거한 뒤 내 관리 진입 시 다시 예약한다. 확인된 전체 스냅샷을 확보한 뒤에만 전체 알림을 교체한다.
