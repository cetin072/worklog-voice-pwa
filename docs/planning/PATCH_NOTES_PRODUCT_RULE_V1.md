# 업무수첩 패치노트 운영 원칙 V1

## 목적
업무수첩의 사용자-facing 변경 이력을 웹과 모바일에서 일관되게 제공한다.

## Source of Truth
1. 개발 중 변경: `.patch-notes/<issue-or-pr>.md`
2. 실제 사용자 공개 변경: `main`에 병합된 완료 기능만 사용자용 패치노트에 반영
3. 웹과 모바일은 가능한 한 하나의 구조화된 패치노트 데이터 소스를 공유

## 완료 조건
사용자에게 보이는 기능/UX/동작이 바뀌는 작업은 다음을 완료해야 한다.
- 관련 `.patch-notes/<issue-or-pr>.md` 추가 또는 갱신
- 테스트/CI와 함께 변경 내역 확인
- main 병합 시 사용자용 패치노트 반영

## 표시 원칙
- 완료된 기능만 표시한다.
- 개발 중/실험 기능을 완료 기능처럼 표시하지 않는다.
- 날짜, 기능명, 사용자에게 체감되는 변화 중심으로 적는다.
- 내부 구현 상세보다 사용자가 무엇이 달라졌는지 우선한다.

## UI
- Web: 설정에서 패치노트 진입 유지
- Mobile: 설정 → 패치노트/업데이트 내역에서 확인 가능해야 함
- 최신 항목을 위에 표시

## 금지
- main에 없는 기능을 사용자 공개 패치노트에 완료로 기록하지 않는다.
- 웹/모바일이 서로 다른 사실관계를 갖지 않도록 한다.
