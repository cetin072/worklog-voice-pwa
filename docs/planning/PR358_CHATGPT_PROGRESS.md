## 이번 변경

- 알림은 예약/취소 전에 원하는 상태와 실제 예약 ID를 영속 기록한다. 모든 알림 변경·복구가 한 작업 큐와 `updateItem`을 공유한다.
- 예약 완료→매핑 저장 전 실패, 오래된 알림 취소 실패, 취소→매핑 저장 전 실패를 재시작 후 복구한다. 정상 매핑과 미완료 작업의 ID는 보호한다.
- OS→매핑 역방향에서 새 소유권 표식이 확인된 고아/중복만 정리한다. 식별 불가능한 레거시 예약은 보존하고 `untracked`로 보고한다. 손상 기록은 빈 상태로 간주하지 않는다.
- 캘린더 목록 조회/후보 추천은 기본값을 정하지 않는다. 개별 이벤트 동기화/이동도 기본값을 덮어쓰지 않는다. 명시적으로 해제한 일정은 자동 재연결하지 않는다.
- 캘린더 생성 전 작업 표식을 기록하고, 이벤트 notes의 고유 표식으로 중단 작업을 재식별한다. 제목·시각만으로 이벤트를 합치거나 지우지 않는다.
- `E_EVENT_NOT_FOUND`만 확인된 부재로 취급한다. 업데이트/조회 일시 실패는 신규 생성으로 이어지지 않는다. 생성/수정/삭제의 결과를 재조회하고, 이동 시 새 매핑과 이전 이벤트 정리 소유권을 먼저 보존한다.
- 캘린더/알림의 읽기→수정→저장 및 OS 작업 전체를 직렬화한다. 일정 취소 대기 큐도 `updateItem`을 사용한다.
- 화면은 DB 기록 성공과 캘린더/알림 반영을 분리한다. resolved `failed` 결과도 오류로 처리하고, 실패 시 마지막 기록과 재확인 버튼을 표시한다. 조회 실패를 기존 연결됨 표시로 숨기지 않는다.
- 전역 알림 표시 핸들러는 앱 layout에서 명시적으로 설치한다.

## 미완료 / 제한 — 숨기지 말 것

- M1 공용 저장의 핵심과 이번 호출부 충돌 보호는 반영됐다. 기기 상태의 계정별 네임스페이스/계정 전환 전체 통합 및 실제 인증 갱신·로그아웃·OS 저장 장애 검사는 남아 있다.
- M2 새 상태 머신의 실행형 검사는 통과했지만 최종 RN 타입/빌드/실기기 권한·알림 수신·캘린더 반영 검사는 CI/기기 검증과 구분해야 한다. 실제 알림 수신 시각·배터리 정책까지 보장하지 않는다.
- 생성 결과를 잃은 캘린더 이벤트의 표식이 사라지거나 원래 범위를 벗어나면 자동 재생성/삭제하지 않고 확인 필요 상태로 보류한다. 조회 범위는 원래 이벤트 주변 ±1일이다. 지원하지 않는 native not-found 코드는 안전하게 실패한다.
- OS가 제공한 캘린더/이벤트/예약 상태 확인까지이며 Google 서버 동기화 완료를 별도로 증명하지 않는다.
- 알림의 소유권 불명 레거시 고아, 손상된 메타데이터는 보존한다. 자동 정리 범위를 무작정 넓히지 않는다.
- 이 작업은 기기 상태 수정이다. M3 음성/이어받기 추가 검증, M4 브리핑 메타데이터 및 일부 조회, 운영 RLS 적용 상태는 별도 미완료다.
- main 병합, 운영 DB/원장/개인 캘린더 변경, 운영 배포, Play Store 제출, 별도 Codex 실행은 하지 않는다.
