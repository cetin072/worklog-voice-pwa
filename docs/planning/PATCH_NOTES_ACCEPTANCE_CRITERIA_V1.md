# 패치노트 Acceptance Criteria V1

사용자에게 보이는 기능 또는 동작이 바뀌는 작업은 다음 조건을 만족해야 완료로 본다.

- `.patch-notes/<issue-or-pr>.md` 기록이 있다.
- 사용자 체감 변화가 한글로 요약되어 있다.
- 개발 중 기능과 main 병합 완료 기능을 구분한다.
- 모바일/웹 중 해당 기능이 노출되는 표면의 패치노트 진입 경로를 유지한다.
- main 병합 후 사용자 공개 패치노트에 반영한다.
- 패치노트 누락을 가능하면 contract test 또는 PR 체크리스트로 방지한다.

패치노트는 내부 구현 로그가 아니라 사용자 변경 이력이다. 내부 SHA, 세부 리팩터링, 비밀 설정값은 사용자 공개 패치노트에 노출하지 않는다.
