# PR #339 Android Human QA Checklist

이 문서는 최신 성공 `Mobile App` workflow의 ARM64 APK에만 적용한다. PR은 Draft를 유지하며, 이 체크리스트 통과만으로 main 병합을 수행하지 않는다.

## 사전 조건

- APK artifact의 head SHA가 PR #339 최신 head와 일치한다.
- `cancel_my_schedule(uuid)`가 QA 대상 Supabase 환경에 적용되어 있다. 미적용이면 일정 취소 항목은 BLOCKED다.
- 테스트용 Android 기기에 Google Calendar 계정과 Calendar 동기화가 켜져 있다.

## 설치와 기본 화면

1. APK를 설치하고 앱을 실행한다. crash 없이 홈, 업무, 일정·알림, 설정 메뉴가 보이는지 확인한다.
2. 상단 상태 표시줄과 하단 시스템 내비게이션 뒤에 버튼·텍스트가 가려지지 않는지 확인한다.

## 로그인

1. 이메일/비밀번호 화면에서 비밀번호 입력을 선택한다.
2. 키보드가 비밀번호 칸과 로그인 버튼을 가리지 않는지 확인한다.
3. 비밀번호 기본 마스킹과 보기/숨기기를 확인한다.
4. Google 로그인 후 `worklog://google-auth`로 앱에 돌아오며 Unmatched Route 없이 홈으로 오는지 확인한다.

## 일정과 Calendar

1. 일정·알림에서 `+ 새 일정`을 누르고 `내일 미팅 테스트 오전 9시`를 저장한다.
2. 새 일정이 내일 날짜와 오전 9시로 표시되는지 확인한다.
3. Calendar 연결·선택에서 writable calendar 목록과 Google 계정 calendar가 보이는지 확인한다.
4. Google Calendar A를 선택해 동기화한 뒤, B로 선택을 바꿔 다시 동기화한다. A event가 제거되고 B에 하나만 남는지 확인한다.
5. 앱을 완전히 종료·실행한 뒤 선택 Calendar가 복원되는지 확인한다.
6. 일정 취소를 누른 뒤 Data Core 일정, device Calendar event, local reminders가 함께 정리되는지 확인한다.

## 알림

1. 미래 일정에서 시작 시/5분 전/10분 전 등 둘 이상을 선택한다.
2. 예약 목록에 각 시각이 보이고, 개별과 전체 취소가 동작하는지 확인한다.
3. 지난 시각 preset은 선택할 수 없거나 이유가 안내되는지 확인한다.
4. 알림을 눌러 해당 일정이 열리는지 확인한다.
5. 그 뒤 앱을 종료하고 홈 아이콘으로 일반 실행한다. 이전 알림 일정으로 자동 진입하지 않아야 한다.

## 업무 검색과 음성메모

1. 업무 → 과거 기록 전체 검색에서 업무명, 기관, 후속조치, 원문 및 완료 업무를 검색한다.
2. 빠른 음성메모를 시작·종료한다. `음성 메모 파일 저장 완료`와 파일명/길이가 보이는지 확인한다.
3. 파일 저장과 업무·브리핑 자동 등록이 별개로 설명되는지, `업무 직접 입력으로 기록하기`가 열리는지 확인한다.

## 판정

- 모두 통과해도 사용자 최종 merge 승인 전에는 Draft/미병합 상태를 유지한다.
