# 모바일 패치노트 구현 방향 V1

## 배경
웹에는 이미 `public/patch-notes.html`, `public/patch-notes.css`, 설정 화면의 패치노트 진입점, `.patch-notes/*.md` 개발 기록이 있다.

## 목표
모바일 앱의 `설정`에서 `패치노트 / 업데이트 내역`을 직접 열어 최근 변경사항을 확인할 수 있게 한다.

## 원칙
- 웹과 모바일이 서로 다른 변경 이력을 갖지 않는다.
- 사용자 공개 패치노트에는 `main`에 병합된 완료 기능만 표시한다.
- 개발 중 변경은 `.patch-notes/<issue-or-pr>.md`에 기록한다.
- 장기적으로 구조화된 공통 데이터 소스(JSON/TS 생성물 등)를 두고 웹과 모바일이 함께 소비한다.
- 현재 웹의 hard-coded HTML을 대규모 리팩터링하지 않고 점진적으로 공통화한다.

## 모바일 UX
설정 화면에 다음 항목을 둔다.

`📝 패치노트 / 업데이트 내역`

진입 시:
- 최신 날짜가 위
- 날짜
- 변경 영역 제목
- 사용자 체감 변화 요약
- 주요 변경 목록

## 구현 단계
1. 현재 웹 패치노트 사실관계를 모바일에서 먼저 재사용
2. 설정 화면에 native 패치노트 화면 연결
3. contract test 추가
4. 이후 공통 구조화 데이터 소스로 웹/모바일 중복 제거

## 완료 조건
- 모바일 설정에서 패치노트 진입 가능
- main에 없는 개발 중 기능은 공개 패치노트에 표시하지 않음
- 새 사용자-facing 기능 PR에는 `.patch-notes` 기록 존재
- 웹/모바일 내용 정합성 테스트 또는 생성 규칙 확보
