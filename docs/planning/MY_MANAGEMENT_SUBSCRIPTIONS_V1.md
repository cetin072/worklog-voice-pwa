# 내 관리 · 구독/정기결제 V1 — 기획 확정본 (2026-11-09)

비공개 테스트 중인 업무수첩에 '내 관리' 메뉴를 더하는 기획. **이 범위로 확정하고, 사용하면서 필요한 것을 추가한다.**
전체 기획 원문: 사용자 확정(2026-11-09 채팅). `AGENTS.md`의 신규 기능 보류 규칙에 대한 예외 승인은 이 기능 한정이다.

## 1. 구성과 순서

'내 관리' 안에 세 기능(구독·정기결제 / 반복 업무·일정 / 습관)을 반복 주기·알림·실행 이력 구조로 묶는다.
**1차는 구독·정기결제만** 만든다. 업무·습관은 같은 구조로 이후에 잇고, 통계는 만들지 않는다.

## 2. 구독 화면 — 전체가 한눈에 보여야 계속 쓸지 판단할 수 있다

- 상단: 이번 달 구독 총액, 연 환산액, 구독 개수 / 그 아래 사업 ○○원 · 개인 ○○원
- 탭 전체 / 사업 / 개인 (탭을 바꾸면 총액도 함께 바뀜)
- 목록: 월 환산 금액 큰 순. 이름, 월 금액, 결제 주기·금액, 다음 결제일, 사용 현황
- 연 결제는 월 환산해 같은 기준으로 비교
- 이번 주 결제 예정·해지기한 임박(7일 이내) 항목은 위쪽에 따로 강조

## 3. 구분

**사업 / 개인 2개로 확정.** 사업체별 구분·공통·세부 카테고리는 제외(필요해지면 추가). 구분은 필드 1개로 저장한다.

## 4. 계속 사용 판단

- 항목마다 '오늘 썼음' 한 번 탭 → 마지막 사용일 기록
- **해지 후보**: 마지막 사용(없으면 등록일) 후 **30일 이상**이고 월 환산 **5,000원 이상**. 구분과 무관하게 전체에서 판단.
  기준값은 초안이며 `CANCEL_CANDIDATE_RULE`(`subscription-model.ts`) 한 곳에서 조정한다.

## 5. 알림

결제일·해지기한 **하루 전 오전 9시(서울)**. 구독마다 앞으로 3번의 결제일 알림을 미리 걸어 앱을 한동안 안 열어도 이어서 울린다(기기당 최대 50건).
권한은 사용자가 '알림 켜기'를 누를 때만 요청한다. 일정(Schedule) 알림 서비스와 섞지 않고 별도 식별자·owner로 분리한다.

## 6. 데이터

`public.subscriptions` (사용자 본인 행만 RLS, 하드 DELETE 없음 — `archived_at` 보관). 금액은 원 단위 정수.
다음 결제일은 저장하지 않고, 사용자가 입력한 **기준일**에서 앱이 계산한다(말일 보정이 누적되지 않음).
업무(WorkRecord)·일정(Schedule)과 섞지 않는 독립 Branch다.

## 7. 이번 구현 범위와 후속

| 항목 | 상태 |
|---|---|
| 요약 화면·탭·목록·추가/수정/삭제(보관)·오늘 썼음·해지 후보 | 구현 |
| 결제일·해지기한 알림 | 구현 |
| 진입 위치: 설정 → 내 관리 → 구독·정기결제 | 구현 (**홈 직접 진입 버튼은 대규모 UI 변경이라 사용자 승인 후 별도**) |
| 한 줄 입력(키보드 마이크 포함) → 규칙으로 읽기 → **저장 전 확인 화면**, 입력 원문 보관, 이름 후보 | 구현 |
| Quick Voice 녹음기 버튼을 구독 화면에 직접 연결 | **후속** — 녹음기가 홈 하단 구조와 업무 저장 경로에 묶여 있어 별도 설계·승인 필요 |
| 반복 업무·습관 | 후속 |
| `subscriptions` 테이블을 운영/QA DB에 적용 | **미적용 — 승인 후 별도** |

## 8. 한 줄 입력 읽기 규칙 (구현됨)

AI 없이 규칙으로만 읽는다(`subscription-utterance.ts`).

- 읽는 것: 사업/개인, 서비스 이름, 금액(`1만 2천원`·`십이만원`·`12,000원`), 주기(`매달`·`월`·`일 년에`·`연` 등), 결제일(`15일`·`3월 10일`·`2026-12-01`)
- 읽지 않고 비워 두는 것: 말하지 않은 값, 애매하거나 충돌하는 값(금액·날짜·구분이 둘 이상), 달력에 없는 날짜, `내일` 같은 상대 표현, `말일`, `N개월` 주기 — 이유를 경고로 알려준다
- 서비스 이름은 **고치지 않는다.** 이미 등록한 이름과 비슷하면 '혹시 이 이름?' 후보만 보여준다.
- 읽은 결과는 항상 확인 화면(입력 원문 + 확인 필요 항목)을 거치고, 원문은 `source_text`에 보관한다(수정 시 덮어쓰지 않음).

## 9. 확정 원칙

- 띄어쓰기·명백한 오타는 자동 보정, 서비스명처럼 애매한 단어는 수정 후보로 표시
- 금액·날짜·반복 주기는 임의로 바꾸지 않고 반드시 확인
- 인식 원문을 남겨 잘못 보정됐을 때 복구
- 구분을 말하지 않으면 확인 단계에서 한 번 묻는다


## 10. 구독 추가 동선 (2026-11-09 사용자 피드백 반영)

- 목록 화면 하단의 한 줄 입력칸을 제거하고 `+ 구독 추가` → 별도 추가 페이지로 이동한다.
- 추가 페이지: 큰 한 줄 입력(자동 포커스, 키보드 마이크로 말하기) → `내용 확인하기`, 또는 `직접 입력하기`(빈 폼). 둘 다 저장 전 확인 폼을 거친다.
- 홈 화면 직접 진입 버튼은 습관·반복 업무가 생길 때 `내 관리` 버튼 1개로 추가한다(큰 UI 변경 → 별도 사용자 승인).
- 앱 내 녹음 버튼 연결(Quick Voice 재사용)은 별도 PR 후속.
