## 2. 첫 실행 — 모델 다운로드

홈의 **빠른 음성 메모 → 녹음 시작**을 누른다.

첫 실행에서는 약 77.7MB multilingual tiny Whisper model이 runtime download될 수 있다.

### PASS

- 다운로드 진행량이 화면에 보임
- 앱이 멈추거나 종료되지 않음
- 다운로드 완료 후 녹음 상태로 진입

### FAIL

- 무한 대기
- 앱 crash
- 다운로드 완료 후에도 녹음 진입 불가
- 매번 모델을 처음부터 다시 받음
- SHA/파일 오류가 반복됨

## 6. 저장 → 브리핑 확인

각 테스트 후 홈 브리핑을 확인한다.

### PASS

- 전사 종료 후 별도 중복 입력 없이 업무가 저장됨
- 저장 성공 메시지가 표시됨
- 브리핑에 새 업무가 나타남
- 날짜/시간 문장은 기존 canonical schedule parser 규칙에 따라 처리됨
- 같은 음성이 두 건 이상 중복 저장되지 않음

### 반드시 확인

Benchmark A 1회 녹음 후 같은 업무가:

`1건 / 2건 이상`

Benchmark B 1회 녹음 후 같은 업무가:

`1건 / 2건 이상`

2건 이상이면 FAIL.

## 8. 실패 복구

### 8-1. STT 실패

가능하면 비정상적으로 짧은 녹음/무음 등으로 실패 경로를 확인한다.

PASS:
- 앱 crash 없음
- 오류 메시지 표시
- `다시 전사` 또는 직접 입력 경로가 나타남
- 실패 때문에 별도 빈 업무가 저장되지 않음

### 8-2. 저장 실패

네트워크를 끊는 등 안전한 방법으로 저장 실패를 재현할 수 있을 때만 확인한다.

PASS:
- 전사문 유지
- `같은 업무 다시 저장` 가능
- 네트워크 복구 후 재시도
- 최종 저장은 1건만 존재

### 8-3. 브리핑 새로고침 실패

재현 가능할 때만 확인한다.

PASS:
- 이미 저장된 업무를 다시 저장하지 않음
- `브리핑만 다시 불러오기` 동작
- 중복 업무 없음

## 10. Provider 채택 판정 기준

whisper.rn을 영구 기본 Provider로 확정하기 전에 최소 아래를 본다.

### 기능 필수

- crash 없음
- 16kHz mono PCM
- 모델 cache 정상
- 자동 저장 정상
- 브리핑 갱신 정상
- 중복 저장 없음
- 수정 정상

### 한국어 품질

특히 행동을 바꾸는 정보는 정확해야 한다.

우선 중요도:
1. 날짜
2. 시간
3. 금액
4. 기관
5. 사람 이름

날짜/시간/금액의 반복 오인식은 Provider 교체 또는 더 나은 모델 비교 사유다.

tiny model 정확도가 부족하면 Core/UI를 수정하지 않고 다음을 검토한다.

1. 더 큰 multilingual Whisper model
2. sherpa-onnx / SenseVoice Provider
3. faster-whisper server baseline
