# ERP와 개인 캘린더 양방향 사용 — 2026-11-09

사용자는 모든 직원의 ERP 기본 캘린더와 선택적 업무수첩 연동을 승인했고, 양쪽에서 등록·수정·삭제가 반영되도록 추가 요청했다. 이 요청에 한정하여 신규 개발을 진행하며 #494의 다른 신규 기능 보류·제품가치 감사는 유지한다.

ERP 이슈: https://github.com/cetin072/taejang_homepage/issues/620
ERP DB/RPC 초안: https://github.com/cetin072/taejang_homepage/pull/621

통합 계정(`dataSchema=worklog`)에만 ‘내 캘린더 · 일정 등록’을 추가한다. 기존 개인 일정 테이블 한 행을 양쪽에서 쓰고 별도 동기화 저장소를 만들지 않는다. 신규 일정은 업무·성과 기록·알림 예약을 만들지 않는다. 회사 공지는 ERP 공개 대상에 따른 읽기 전용이며 업무수첩 개인 일정 목록에 복제하지 않는다. 기존 업무 연결 일정은 연결 업무에서 수정한다.

등록·수정 시 제목·날짜만 필수이고 시간은 선택이다. 기존 종료 날짜·시간·장소·메모를 읽어 유지하며 상세에서 변경한다. 종일 일정 종료일은 포함 날짜다. 삭제는 동일 행의 취소다. ERP RPC의 요청 ID/수정 시각 검사를 재사용해 중복과 덮어쓰기를 방지한다. 실패·충돌 시 입력을 유지하고 닫기 전에 확인한다. 토큰을 확인된 본인에 고정하고 계정 변경/화면 종료 이후 응답을 폐기한다. 녹음 중에는 기존 이동 보호를 유지한다.

검증: TypeScript, 전체 Node 회귀 검사, 실제 TSX의 등록/충돌/재시도/수정/삭제 상태 동작 검사, Android Metro export. ERP 쪽 일회용 로컬 Supabase CI가 양방향 REST/RPC 동일 행 저장과 본인 소유권·공지 공개 대상을 검증한다. 실제 기기 터치·키보드·새로고침 시간과 업무시간 절감은 아직 미측정이다. 새 APK/Play/운영 DB 변경을 이 작업에서 실행하지 않는다.

적용 순서: ERP RPC 승인·적용 → 양쪽 코드 승인·반영 → 요청된 QA 시 설치본 검수. RPC 준비 전 업무수첩에서는 ‘준비 중’ 오류를 표시하고 기존 업무 기록은 유지한다. 다른 계정/다른 프로젝트를 이메일로 자동 연결하지 않는다. 현재 설치본에는 이 미병합 변경이 포함되어 있지 않다.
