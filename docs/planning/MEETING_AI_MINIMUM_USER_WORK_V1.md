## 1. 사용자 관점에서 진짜 해결할 문제

기술적 완료 기준인 '녹음을 텍스트로 전사할 수 있다'는 충분하지 않다.
회의 후 사용자가 긴 전사문을 읽고, 요약·결정사항·후속 업무를 다시 수기로 추려서 다른 앱에 등록해야 한다면 업무가 늘어난다.

**제품 목표: 회의 녹음 종료 → 자동 전사 → 회의록 초안(핵심 요약·결정사항·담당자/기한이 있는 후속 업무 *후보*) → 사용자 검토·수정·확정 → 저장, 선택한 업무만 기존 Work/Schedule에 연결.**

기본 화면은 긴 텍스트가 아닌 **확인 가능한 결과**이다. 원본 전사문은 필요할 때 펼쳐보는 근거 자료로 둔다.

## 2. 실행 단계 (한 번에 하나, 순차 검증)

### Stage A: 현재 녹음/STT 실제 작동 검증
- 기존 녹음/저장/재생/목록/편집/공유 유지.
- Android native MediaExtractor/MediaCodec M4A → PCM WAV → 현재 Whisper 모델 재사용.
- 1~5분 실제 녹음으로 저장·인식·재실행 후 잔존 검증, 이후 30/60분 확장.
- 처리시간/배터리/메모리/한국어 고유명사·날짜·금액 인식률 측정. 추측이나 CI 통과로 대신하지 않는다.
- 실패해도 M4A 원본, 사용자의 수기 문서, 성공한 Transcript checkpoint 보존.
- 개발 경계: [PR #493](https://github.com/cetin072/worklog-voice-pwa/pull/493). 현 시점 UI는 QA 전용이고 정식 자동 전사 승인 상태가 아님.

### Stage B: 회의록 분석 '한 건' 시제품
- **새 앱·새 DB·범용 AI 프레임워크를 만들지 않는다.**
- 이미 보관된 Transcript V1을 입력받아 기존 회의록 파일의 초안 필드로 연결할 **분석 Adapter 한 개**만 시험.
- 출력 최소 단위: (1) 요약 (2) 결정사항 (3) 후속 업무 후보 (4) 확인 필요. 시간·담당자를 추측하지 않으며 텍스트에서 찾은 근거 구간을 가능한 범위에서 첨부한다.
- Transcript 원문은 독립적으로 보존하고 AI 분석 결과가 원본을 덮어쓰지 않도록 한다.
- 실제 한국어 회의 1~3건에서 누락·환각·수정시간 확인 전 자동 확정 금지.
- 분석기 구현은 기존 로컬 LLM/검증된 런타임을 우선 비교한다. 직접 언어모델·STT 재구현 금지.

### Stage C: 사용자 조작 최소화
- Stage A/B가 충분히 검증되면 기본 동선을 **회의 종료 → [회의록 만들기] 1회 → 초안 확인/수정 → 확정**으로 단축.
- 음성 전사·전사문 가져오기·요약 요청·복사·붙여넣기 여러 단계를 기본 플로우에서 제거하되, 안전한 검토/재시도/원문확인 기능은 유지.
- 확정된 업무 후보만 기존 WorkRecord/Schedule API를 통해 생성. 중복 등록 방지·날짜/시간/권한·알림 확인을 지킨다.
- 기계적으로 추정한 책임자/기한/계약 조건/금액을 사용자 승인 없이 등록하지 않는다.

### Stage D: 자동화/백그라운드 (실사용 필요 시)
- 먼저 Stage C의 한 번 실행 방식으로 사람의 실제 시간을 충분히 줄이는지 실측한다.
- 필요성이 확인될 때에만 녹음 종료 후 자동 시작, 백그라운드 처리, 완료 알림을 고려.
- Android OS 생명주기/중단·재개/전력·메모리·데이터 소실 안전 경계가 검증되기 전 무조건 백그라운드 자동실행 금지.

## 3. 무료·총비용 평가

- 현 Whisper 기반 로컬 STT는 원칙적으로 **외부 STT API 호출료 0원** 경로다. 모델 다운로드·저장공간·배터리·기기 처리시간은 공짜가 아니다.
- AI 요약도 무료 로컬 소형 모델로 **가능성은 검증**하되, 실측 없이 '노션 AI와 동등'하다고 약속하지 않는다.
- 모바일 메모리·맥락길이 한계가 확인되면 30~60분 전사를 구간별로 분리해 요약→결합하는 최소 방식을 검토.
- 모바일 로컬 모델 vs 이미 보유한 PC 처리 vs 외부 STT/LLM API를 **정확도, 한국어 고유명사, 처리 시간, 수정 시간, 실패율, 보안, 유지비**로 비교.
- 소액 유료 API가 총 업무시간을 크게 줄일 경우 무조건 배제하지 않지만, 외부 전송·비용·보존정책은 **사용자 명시 승인 전 적용하지 않는다**.
- 녹음 파일을 Notion/AI API/ERP로 자동 업로드하지 않는다. 업무별 민감정보·동의 문제를 사전에 검토한다.

## 4. 데이터 단일 주인과 안전 경계

| 데이터 | 소유자 | 원칙 |
|---|---|---|
| 원본 녹음 M4A | 기기 원본 | 임의 수정·삭제·자동 업로드 없음 |
| 원시 Transcript | 녹음 ID와 연결된 별도 체크포인트 | 원문 보존, AI 요약으로 덮어쓰기 금지 |
| 수정 가능한 회의록 | 기존 회의록 저장 기능 | 사용자 확인·저장, 실패 시 입력 유지 |
| 후속 업무/일정 | 기존 WorkRecord/Schedule Core | 후보와 확정 분리; 명시적 선택만 생성 |
| 임시 WAV/처리 캐시 | 기기 임시 저장소 | 성공적 보관 확인 후 안전하게 정리 |

동일 개념을 위해 별도 노션 DB/회사용 DB/휴대폰 DB를 중복 신설하지 않는다. 기존 기능/어댑터/모델 재사용이 우선이다.

## 5. 성공 판정은 '업무 시간'으로

- 비교 기준: 회의 후 원래 하던 노션 AI/수기 메모/문서 작성/업무 등록 절차 vs 업무수첩 V1.
- **전체 완료시간** = 사용자 입력·버튼·대기·문서 열기·정확도 수정·재확인·공유·업무 등록·실패 후 복구까지.
- 같은 5/30분 회의에서 결과 정확도, 빠진 결정사항, 거짓 담당자/기한, 교정에 쓴 시간, 앱 이동 횟수, 전사/요약 비용, 배터리 부담을 함께 측정.
- 제품 목표 예시: 30분 회의 후 검토·확정 작업이 약 3분 이내. **실측 성능/보장은 아니며 검증용 가설이다.**
- 결과가 빈약해 수동 교정에 15분 이상 걸리면 무료 AI라도 사용 가치가 없다. 더 작은 범위로 단순화하거나 방식 변경한다.

## 6. 변경/재개 결정 게이트

1. [제품가치 전수검사 #494](https://github.com/cetin072/worklog-voice-pwa/issues/494)를 먼저 완료·검토한다.
2. 기능 유지·수정·통합·중단 우선순위를 사용자와 확정한다.
3. 그 뒤 기존 Whisper STT의 실제 기기 검증을 하고, Stage B의 작은 AI 회의록 분석 시제품을 착수한다.
4. QA APK는 사용자가 요청할 때만 기존 패키지·서명으로 업데이트 제작. 정식 Play/운영 배포는 별도 명시 승인.
5. **새로운 로컬 AI 프레임워크, 클라우드 인프라, 작업 큐, 스키마를 미래를 대비한다는 이유만으로 미리 만들지 않는다.**
