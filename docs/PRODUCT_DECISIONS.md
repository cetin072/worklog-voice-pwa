# Product Decisions

제품의 큰 UX·구조 결정을 Git 커밋 메시지와 별도로 기록합니다.

## 2026-09-16 — Home UX: Thumb-first Voice Capture

### 문제
업무수첩의 핵심 기능인 음성 기록 버튼이 홈 상단에 있어 한 손 사용 시 엄지손가락 접근성이 떨어졌다.

반면 `입력 지우기` 같은 보조 기능이 같은 핵심 조작 카드 안에서 큰 면적을 차지해, 가장 중요한 행동과 보조 행동의 우선순위가 충분히 분리되지 않았다.

또한 기존 홈에는 상세 브리핑 기능이 이미 있었지만, 앱을 열자마자 `오늘 무엇을 먼저 봐야 하는지`를 짧게 파악하는 용도로는 정보량이 많았다.

### 결정
- 핵심 음성 기록 버튼을 화면 하단 중앙의 엄지 도달 영역으로 이동한다.
- 오른손·왼손 사용자를 함께 고려해 좌우 끝이 아닌 중앙을 기본 위치로 한다.
- 하단 제스처 영역과 겹치지 않도록 safe-area 여백을 둔다.
- 음성 기록 시작과 종료는 같은 CTA 위치에서 수행한다.
- 상단에는 `오늘의 브리핑`을 두고 오늘 일정, 기한 경과, 후속조치 필요, 다음 일정만 우선 노출한다.
- 전체 업무 목록과 기존 상세 브리핑은 제거하지 않고 `전체 보기`를 통해 접근한다.
- 홈 요약을 위한 별도 백엔드나 중복 데이터를 만들지 않고 기존 Briefing V2 렌더 결과를 재사용한다.
- `입력 지우기`, 직접 입력, 수동 저장 같은 보조 조작은 핵심 음성 CTA보다 낮은 시각적 우선순위에 둔다.

### 목표
업무수첩의 메인 경험을 다음 흐름으로 만든다.

`오늘 상황 확인 → 음성 기록 → 업무화`

사용자가 앱을 열고 시선을 크게 이동하거나 버튼 위치를 다시 찾지 않아도, 현재 상황을 확인한 뒤 한 손으로 바로 기록을 시작하고 같은 위치에서 종료할 수 있어야 한다.

### 보존 원칙
- 기존 검색, 설정, 상세 브리핑, 직접 입력, 저장, 기록 정제 기능은 임의로 제거하지 않는다.
- Briefing V2 / Data Core를 source of truth로 유지한다.
- Home UX는 기존 도메인 로직 위에 얇은 표현 계층으로 추가한다.

## 2026-09-16 — Home UX: Voice Quick Dock

### 문제
하단 중앙의 큰 음성 CTA로 녹음 시작과 종료는 쉬워졌지만, 녹음 중 취소하거나 키보드 입력으로 전환하려면 여전히 화면 안의 별도 버튼을 찾아야 했다.

특히 업무 목록을 스크롤하면서 플로팅 마이크를 사용하는 상황에서는 핵심 입력 행동과 보조 행동의 위치가 떨어져 있어 한 손 흐름이 끊길 수 있었다.

### 결정
- 기존 큰 원형 음성 CTA를 중심으로 좌·우·상단에 작은 원형 보조 요소를 배치한 `Voice Quick Dock`을 사용한다.
- 좌측 작은 원은 `✕ 취소`로 표시하고 기존 `입력 지우기` 동작을 재사용한다.
- 우측 작은 원은 사용자가 바로 이해할 수 있게 `✏️ 메모`로 표시하되, 실제 동작은 기존 직접 입력 이동·포커스를 재사용한다.
- 상단 작은 원은 별도 액션을 추가하지 않고 녹음 중 `00:00` 형식의 경과시간을 보여주는 상태 표시로 사용한다.
- 가운데 큰 마이크는 계속 가장 큰 시각적 우선순위를 가지며 `음성 기록 → 종료`의 동일 위치 상태 전환을 유지한다.
- 좌·우 버튼은 왼손·오른손 모두 접근하기 쉽도록 중앙 CTA 기준 대칭으로 배치한다.
- 하단 제스처 영역을 침범하지 않도록 Quick Dock 전체에 safe-area 여백을 적용한다.

### 이유
정지 기능을 위쪽에 하나 더 만들면 가운데 `종료`와 역할이 중복된다. 위쪽을 녹음 시간 표시로 사용하면 현재 상태를 확인하면서도 조작 모델은 단순하게 유지할 수 있다.

또한 새로운 취소·메모 저장 로직을 만들지 않고 이미 검증된 기존 지우기·직접입력 동작을 호출하면 저장, 초안, 음성인식, Data Core 경계를 건드리지 않고 한 손 UX만 개선할 수 있다.

### 목표
`확인 → 말하기 → 필요하면 취소/메모 → 같은 자리에서 종료`

사용자가 업무 목록 어느 위치를 보고 있더라도 엄지를 크게 이동하지 않고 음성 기록과 주요 보조 입력 행동을 처리할 수 있어야 한다.

### 보존 원칙
- `#mic`, `#clear`, `#manualEntry`, `#text`의 기존 기능 계약을 유지한다.
- Voice Quick Dock은 Home UX 표현 계층에서 기존 동작을 연결하는 방식으로 구현한다.
- 저장/API/Data Core 로직을 Quick Dock 안에 복제하지 않는다.

## 2026-09-16 — Home UX: Brand Launch Splash

### 문제
앱을 실행할 때 짧은 로딩 구간이 있지만, 현재는 제품 이름과 핵심 메시지가 충분히 드러나지 않아 `업무수첩`이라는 브랜드를 기억시키는 접점으로 활용되지 못했다.

반대로 브랜딩을 위해 별도 영상·애니메이션·대형 이미지나 강제 대기 시간을 추가하면 앱 시작이 무거워지고 핵심 가치인 빠른 기록을 방해할 수 있다.

### 결정
- `platform-auth-loading` 동안 이미 존재하는 환영 카드를 전체 화면 브랜드 시작 화면으로 재사용한다.
- 기존 `/icons/icon-192-v3.png`를 앱 아이콘으로 사용한다.
- 제품명은 `업무수첩`, 메인 슬로건은 기존 제품 문구인 `말하면 기록되고, 일정까지 한눈에`로 통일한다.
- 시작 화면을 위한 별도 API 호출, 외부 폰트, 신규 이미지 파일은 추가하지 않는다.
- 인증 초기화와 브랜드 표시를 병렬로 진행하고, 브랜드 표시가 앱의 데이터 준비를 막지 않게 한다.

### 이유
기존 로딩 구간을 브랜드 노출에 활용하면 큰 자산이나 별도 화면을 추가하지 않고도 앱의 이름과 핵심 약속을 반복적으로 각인시킬 수 있다.

또한 기존 환영 카드와 아이콘을 재사용하면 DOM과 네트워크 비용을 거의 늘리지 않고 일관된 첫 화면을 만들 수 있다.

### 목표
`앱 실행 → 업무수첩 브랜드 인지 → 오늘 상황/음성 기록으로 진입`

### 보존 원칙
- 로컬 세션 힌트와 원격 `currentUser` 검증은 그대로 유지한다.
- 시작 화면은 브랜딩 계층일 뿐 인증·데이터·저장 로직을 소유하지 않는다.

## 2026-09-16 — Home UX: Brand Launch First-paint Guarantee

### 관찰
Home UX 0.4는 `platform-auth-loading` 상태가 유지되는 동안만 브랜드 화면을 보여주도록 했지만, 로컬 세션 힌트가 매우 빠르게 적용되는 기기에서는 첫 브라우저 paint 전에 해당 클래스가 제거될 수 있었다. 코드상 스플래시가 존재해도 실제 사용자는 보지 못하는 상황이 생겼다.

### 결정
- 인증 상태 전환과 `platform-auth-loading` 제거를 분리한다.
- 로컬 세션 힌트와 원격 인증 검증은 즉시 시작해 앱 초기화가 뒤에서 계속 진행되도록 한다.
- 첫 paint를 보장하기 위해 `requestAnimationFrame` 이후 약 `420ms`의 짧은 브랜드 노출 시간을 둔 뒤 다음 frame에서 로딩 클래스를 제거한다.
- 로딩 클래스가 남아 있는 동안에는 `platform-session-hint`, `platform-signed-in`, `platform-legacy-user`, `platform-auth-unavailable` 상태가 붙어도 브랜드 화면이 우선 표시되도록 CSS 상태 우선순위를 고정한다.
- 새 API, 외부 라이브러리, 외부 폰트, 신규 이미지 파일은 추가하지 않는다.

### 이유
브랜딩 화면이 실제로 한 번도 paint되지 않는다면 기능이 존재해도 사용자 경험상 없는 것과 같다. 약 0.4초의 짧은 시각 노출은 의도적으로 보장하되, 그 시간 동안 인증·데이터 초기화를 멈추지 않음으로써 앱 자체를 무겁게 만들지 않는 쪽을 선택한다.

### 보존 원칙
- 브랜드 노출 시간은 데이터 로딩 대기시간으로 사용하지 않는다.
- 음성 기록, Briefing, 저장, 검색, Data Core 로직에는 영향을 주지 않는다.
- 향후 시작 성능이 더 빨라져도 브랜드 화면은 최소 한 번 실제 paint되어야 한다.
